# RAGX 混合检索排查指南

Retrieval-Augmented Generation (RAG，检索增强生成) 混合检索通常指稠密向量检索 + 稀疏/关键词检索，再融合重排。在落地时，问题大多不出在“模型不够强”，而出在工程细节和数据处理上。下面按检索链路的各个环节梳理常见踩坑点。

## 缩写说明

| 缩写 | 全称 | 说明 |
| --- | --- | --- |
| BM25 | Best Matching 25 | 词法相关性排序函数，用于关键词召回。 |
| HyDE | Hypothetical Document Embeddings | 通过生成假设性文档改善短查询向量表达。 |
| LLM | Large Language Model | 大语言模型，负责最终答案生成。 |
| RAG | Retrieval-Augmented Generation | 检索增强生成。 |
| RRF | Reciprocal Rank Fusion | 基于排名的多路召回融合方法。 |

完整缩写表见 [RAGX Abbreviations](abbreviations.md)。

## 一、分块(Chunking)环节

- **切块粒度不匹配查询粒度**:块太大召回的噪声多、稀释了相关信号且超出重排上下文;块太小则语义不完整,答案被切断在两块之间。建议按语义/结构(标题层级、段落)切分,而非固定字符数硬切。
- **丢失上下文锚点**:把表格、列表、代码从其标题和上文中剥离,块本身失去指代对象(如"该指标""上表"无法理解)。常见补救是 chunk 携带父级标题、文档标题等元数据,或采用 small-to-big / parent-document 检索。
- **重叠设置不当**:无重叠导致边界信息丢失,重叠过大造成索引膨胀和重复召回。

## 二、稀疏检索(Best Matching 25, BM25/关键词)环节

- **分词与语言处理缺失**:中文未做合适分词、未处理停用词和大小写,导致 BM25 形同虚设。中英混排、专有名词、代码标识符尤其容易踩坑。
- **同义词/术语鸿沟**:用户用口语词,文档用专业术语,纯词面匹配召回为零——这本是稠密检索要补的短板,但若稀疏侧权重设过高会重新放大该问题。

## 三、稠密检索(向量)环节

- **Embedding 模型与领域不匹配**:通用 embedding 在垂直领域(法律、医疗、内部术语)区分度差。务必用业务数据评估,必要时微调。
- **query 与 doc 不对称**:短问题和长文档块在向量空间分布差异大。应使用支持非对称检索的模型,或用 query 改写/Hypothetical Document Embeddings (HyDE，假设性文档向量) 拉近分布。
- **归一化与距离度量不一致**:索引用内积、查询当余弦,或未归一化,导致打分错乱。
- **多语言/跨语言场景**:用了单语模型却有跨语言检索需求。

## 四、融合与重排(Fusion & Rerank)——最容易出错的环节

- **分数直接相加**:Best Matching 25 (BM25) 分数和向量相似度量纲完全不同,直接加权融合会让某一路主导结果。**优先用 Reciprocal Rank Fusion (RRF，倒数排名融合) 基于排名而非原始分数融合**,对量纲不敏感、鲁棒性更好。
- **融合权重拍脑袋**:稠密/稀疏权重(alpha)没有用真实查询集调过,凭直觉设 0.5。不同查询类型(事实型 vs 语义型)最优权重不同。
- **省掉二阶段重排**:混合召回后只靠融合分数截断 Top-K,精排缺失,真正相关的文档排不到前面。RAGX 可通过 `RAG_RERANKER_BACKEND=cross_encoder|colbert|none` 在 Cross-Encoder、ColBERT 和无重排之间切换。
- **重排候选集太小**:rerank 前的召回 K 设得太小(如各路只取 5 条),好文档在召回阶段就被漏掉,重排再强也无力回天。

## 五、检索与生成衔接环节

- **Top-K 与上下文窗口失衡**:塞太多块进 prompt,Large Language Model (LLM，大语言模型) "迷失在中间"(lost in the middle),关键信息在长上下文中部被忽略。
- **缺少相关性阈值/兜底**:无论检索质量如何都强行喂给 Large Language Model (LLM，大语言模型),知识库里没有答案时仍生成,导致幻觉。应设打分阈值,低于阈值时回答"未找到"。
- **未做引用溯源**:无法定位答案来自哪个块,难以验证和排错。

## 六、系统与评估层面

- **没有分环节评估**:只看端到端答对率,出问题无法定位是召回漏了、重排排错了还是生成幻觉。应分别监控**召回率(retrieval recall)、重排命中率、生成忠实度(faithfulness)**。
- **缺乏真实评测集**:用合成问题调参,与线上真实 query 分布不符。
- **元数据过滤缺失或过严**:不带权限/时间/类目过滤会召回越权或过期内容;过滤条件过严又把候选集裁空。
- **索引更新与一致性**:文档更新后向量库与稀疏索引未同步重建,两路检索看到不同版本的数据。
- **成本与延迟**:双路检索 + Cross-Encoder 重排显著增加延迟和算力成本,高并发下需做缓存、异步或重排器蒸馏。
